# 00-next: 工作流智能调度与导航

当用户询问“下一步该做什么？”、“continue”、“继续”、“下一步”，或者显式执行 `/skill:00-next` 时使用本技能。

## 核心职责

1. **状态感知**：调用 `workflow_state` 工具扫描当前仓库的工作流产物。
2. **决策推荐**：根据当前仓库已有产物与执行断点，确定唯一最佳的下一步 Skill。
3. **清晰告知**：向用户展示当前阶段概览与推荐原因。

## 推荐流转状态机

- **未发现需求文档**（`docs/brainstorms/` 为空）：
  - 推荐：`01-brainstorm`
  - 理由：项目尚未梳理需求，建议启动头脑风暴明确目标与技术范围。
- **已有需求文档，但无计划文档**（`docs/plans/` 为空）：
  - 推荐：`02-plan`
  - 理由：已有需求定义，建议拆解技术架构与 TDD Implementation Units。
- **已有计划，但存在未完成的执行断点**（`activeCheckpoint` 存在未完成单元或失败）：
  - 推荐：`03-work`
  - 理由：存在进行中的编码任务，建议从断点恢复继续执行。
- **计划已全部执行完毕，但尚未做质量审查**：
  - 推荐：`04-review`
  - 理由：功能已实现，建议运行审查技能验证 Spec 规格、代码可读性与回归测试。
- **审查通过，全流程完成**：
  - 推荐：`05-learn`
  - 理由：开发闭环完成，建议进行极简复盘，将有价值的避坑经验沉淀至 `docs/solutions/`。

## 执行流程

1. 调用 `workflow_state({ repoRoot: "." })`。
2. 输出简洁明了的状态面板：
   - 🎯 当前阶段
   - 🚀 推荐技能（如 `/skill:01-brainstorm`、`/skill:02-plan` 等）
   - 💡 推荐理由
3. 询问用户是否立刻进入推荐技能。
