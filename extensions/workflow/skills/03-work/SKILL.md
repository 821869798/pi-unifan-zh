# 03-work: 自主循环干活与严格 TDD 编码执行

当计划制定完毕后（已有 `docs/plans/`），执行本技能（`/skill:03-work` 或口述“执行03”、“开始干活”）直接进入自主编码推进阶段。

> ⚡ **原生自主循环驱动机制 (Autonomous Driving Loop)**：
> 无需记忆任何多余命令！进入 `03-work` 后，工作流扩展会自动在底层接管事件循环，按计划顺序逐个推进 Implementation Units。**每个单元完成后自动跨回合无缝驱动下一个单元，不做完所有规划单元绝不停机！**

---

## 🎯 启动与交互方式

- **启动自主干活**：
  直接运行 `/skill:03-work`（或在 00-next 引导下确认执行）。扩展自动定位 `docs/plans/` 下最新计划，解析所有 Implementation Units，并从上次断点处无缝接力。
- **随时暂停**：
  干活过程中，若需打断，直接在输入框输入 `暂停`、`停止`（或按下终端 `Esc` 键），扩展将安全保存现场断点并挂起循环。
- **恢复干活**：
  随时再次调用 `/skill:03-work` 或发送 `继续`，即可从断点处再次恢复自主循环推进。
- **查看状态**：
  随时运行 `/workflow`，即可查看当前 03-work 自主推进进度看板。

---

## 🛡️ 核心工程纪律与硬门禁

1. **严格 TDD (红-绿-重构)**：
   - 编写或补充对应当前 Unit 的测试用例（RED）。
   - 实现让测试通过的最简业务代码（GREEN）。
   - 运行该单元的确定性验收命令，确保 100% 绿灯。
2. **断点自动同步 (Session Checkpoint)**：
   - 每完成一个 Unit 并验证通过后，**必须立即调用**：
     `session_checkpoint({ operation: "save", planPath: "...", completedUnits: ["Unit X"] })`
   - 底层引擎检测到断点更新后，会自动跨回合调度下一单元，模型绝不中途停下向用户求确认。
3. **Stop-the-line (遇错即停硬门禁)**：
   - 当遇到非预期错误时，优先排查根因自愈。
   - **3次失败熔断阀门**：同一单元若连续 3 次排查修复仍失败，底层引擎强制启动 Stop-The-Line 保护，立即暂停自主循环并如实向用户报告现场，严禁盲目乱试或绕过未通过的测试。
4. **全量闭环与自动转交**：
   - 当所有 Implementation Units 均已通过验收命令时，自主循环自动宣告完成，并**自动流转至 `/skill:04-review` 进行全量代码审查与回归验证**。

## 🔄 循环推进状态机

```
[读取计划 / 恢复断点]
         │
         ▼
 ┌──> [选取待办 Unit] ──> [编写/更新测试 RED]
 │                               │
 │                               ▼
 │   [保存断点 SAVE] <── [验证通过 GREEN] <── [编写实现代码]
 │         │
 │         ▼
 └── (还有待办 Unit?) ──> 是: 引擎底层自动注入下一回合 (跨回合自主续跑)
                     └── 否: 全部完成！自动流转至 04-review 审查
```
