# 03-work: 自主循环干活与严格 TDD 编码执行

当计划制定完毕后（已有 `docs/plans/`），执行本技能（`/skill:03-work`）直接进入自主编码推进阶段。

> ⚡ **连续自主推进机制 (Autonomous Continuous Loop)**：
> 进入 `03-work` 后，必须按计划顺序逐个推进所有 Implementation Units。**严禁完成一个步骤就停下等待用户！每个单元完成后立即自主推进下一个单元，不做完所有规划单元绝不停机！**

---

## 🎯 启动与交互方式

- **启动自主干活**：
  直接运行 `/skill:03-work`（亦可在 00-next 引导下确认执行）。自动定位 `docs/plans/` 下最新计划，智能解析所有 Implementation Units（或步骤/任务），并从上次断点处接力推进。
- **随时暂停**：
  干活过程中，若需打断，直接在输入框输入 `暂停`、`停止`（或按下终端 `Esc` 键），扩展将安全保存现场断点并挂起循环。
- **恢复干活**：
  随时再次调用 `/skill:03-work`，即可从断点处再次恢复自主循环推进。
- **查看状态**：
  随时运行 `/workflow`，即可查看当前 03-work 自主推进进度看板。

---

## 🛡️ 核心工程纪律与连续推进铁律

1. **连续自主推进（严禁完成单步即停）**：
   - 当任务目标或计划中包含多个步骤时，**绝对严禁每完成一步就停下向用户汇报或等待用户输入**！
   - 每完成一个 Unit 并验证通过、保存断点后，**必须立即自主推进下一个待办 Unit**，连续执行直到计划中的所有 Implementation Units 全部完成并通过验证！
   - 即使单次回合达到上下文或工具调用限制而结束，底层工作流扩展也会在 `agent_end` 自动注入续跑指令无缝接力下一单元。
2. **严格 TDD (红-绿-重构)**：
   - 编写或补充对应当前 Unit 的测试用例（RED）。
   - 实现让测试通过的最简业务代码（GREEN）。
   - 运行该单元的确定性验收命令，确保 100% 绿灯。
3. **断点自动同步 (Session Checkpoint & Markdown Checkboxes)**：
   - 每完成一个 Unit 并验证通过后，**必须立即调用**：
     `session_checkpoint({ operation: "save", planPath: "...", completedUnits: ["Unit X"] })`
     或在计划 Markdown 对应条目勾选 `[x]`。
   - 记录断点后不要停顿，立即开始下一单元。
4. **Stop-the-line (遇错即停硬门禁)**：
   - 当遇到非预期错误时，优先排查根因自愈。
   - **3次失败熔断阀门**：同一单元若连续 3 次排查修复仍失败，底层引擎强制启动 Stop-The-Line 保护，立即暂停自主循环并如实向用户报告现场，严禁盲目乱试或绕过未通过的测试。
5. **全量闭环与自动转交**：
   - 当所有 Implementation Units 均已通过验收命令时，自主循环宣告完成，并**自动流转至 `/skill:04-review` 进行全量代码审查与回归验证**。

## 🔄 循环推进状态机

```
[读取计划 / 恢复断点]
         │
         ▼
 ┌──> [选取待办 Unit] ──> [编写/更新测试 RED]
 │                               │
 │                               ▼
 │   [保存断点 SAVE] <── [验证通过 GREEN] <── [编写实现代码]
 │         │
 │         ▼
 └── (还有待办 Unit?) ──> 是: 立即自主执行下一个 Unit (连续推进，绝不停机等待)
                     └── 否: 全部完成！自动流转至 04-review 审查
```
